# העסק של נופר

אפליקציה לניהול עסק, בעברית ובכיווניות RTL. מותאמת לאייפון ולמחשב: אירועים, לקוחות, תשלומים, יומן, סיכומים, דוחות וייצוא CSV לאקסל.

## הפעלה מקומית

נדרש Node.js 22.12 ומעלה (נבדק עם Node.js 24).

```powershell
npm ci
Copy-Item .env.example .env
npm run db:generate
npm run db:local
```

השאירו את מסוף בסיס הנתונים פתוח. במסוף נוסף:

```powershell
npm run db:migrate
npm run dev
```

כתובת: http://localhost:3001

בסיס הנתונים המקומי הוא PostgreSQL באמצעות PGlite, ונשמר בתיקיית `.local-db`. הוא מיועד לפיתוח ובדיקות בלבד. אל תמחקו תיקייה זו אם יש בה מידע שברצונכם לשמור. במצב פיתוח ללא סיסמה, הגישה פתוחה ברשת המקומית; הגדירו סיסמה לפני שימוש עם נתוני עסק אמיתיים.

לא נטענים לקוחות או אירועים לדוגמה. המיגרציה מוסיפה רק את סוגי האירועים הראשוניים. `npm run db:seed` משלים סוגים חסרים ללא שינוי מידע קיים.

## חיבור ל־Neon ופריסה

1. צרו בסיס נתונים **נפרד** לעסק ב־Neon. אין להשתמש בבסיס הנתונים של אפליקציית התקציב.
2. הגדירו בסביבת הפריסה `DATABASE_URL` עם הכתובת המאוגמת של Neon ו־`DIRECT_URL` עם הכתובת הישירה למיגרציות. השתמשו בחיבור SSL לפי הגדרות Neon. לעולם אל תכניסו סודות ל־Git.
3. הגדירו `APP_PASSWORD` ארוכה וייחודית ו־`SESSION_SECRET` אקראי באורך 32 בתים ומעלה. יצירת סוד לדוגמה: `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"`.
4. הריצו `npm run db:migrate` מול בסיס הנתונים הייעודי, ואז `npm run build` ו־`npm start`, או פרסו בספק שתומך ב־Next.js ובסביבת Node.js.
5. הפעילו HTTPS. במצב production המערכת חוסמת גישה ללא הגדרת הסיסמה והסוד. הגישה מוגנת בעוגיית HttpOnly חתומה, בעלת תוקף של שבעה ימים. יציאה מוחקת את העוגייה במכשיר הנוכחי. שינוי הסוד מבטל את כל ההפעלות.

הנתונים נשמרים ב־PostgreSQL וממשיכים להתקיים אחרי אתחול או פריסה מחדש. אין מעבר אוטומטי מנתוני הפיתוח המקומיים ל־Neon; יש לבצע גיבוי ושחזור אם מתחילים להשתמש מקומית לפני החיבור.

התחברות מיועדת לבעלת עסק אחת. יש הגבלת ניסיונות כניסה בזיכרון של כל תהליך; בפריסה עם כמה שרתים מומלץ להוסיף הגבלת קצב משותפת דרך ספק האירוח. אין רישום עצמי או מערך משתמשים מרובים בגרסה זו.

## כללי חישוב

- סכומים נשמרים באגורות כמספרים שלמים. שולם = סכום רשומות התשלום. יתרה = מחיר פחות סכום התשלומים. אין שדה שולם כפול בבסיס הנתונים.
- הכנסה חודשית היא שווי האירועים לפי **תאריך האירוע**. הסכום שנגבה בדוח הוא התשלומים עבור אותם אירועים, גם אם שולמו בחודש אחר. אין כאן דוח תזרים לפי תאריך תשלום.
- אירועים שבוטלו נשמרים בהיסטוריה, אך מוחרגים מסיכומי הכנסה וגבייה. המערכת לא מבצעת החזרים כספיים; תשלומים קיימים נשארים בהיסטוריה ובייצוא התשלומים.
- אירוע במחיר אפס נחשב משולם. אי אפשר לשלם מעל היתרה או להפחית מחיר מתחת לסכום שכבר שולם.
- מספרי טלפון ישראליים עוברים נרמול: `+972`, `00972` ומספר מקומי מזהים אותו לקוח. מספר טלפון ייחודי מונע כפילות.
- אירוע לאותו לקוח, באותו תאריך ובאותו סוג, גורר אזהרה. אפשר לאשר אירוע נוסף במפורש.
- שמירות ותשלומים משתמשים במזהה בקשה למניעת כפילות בעת ניסיון חוזר. תשלומים ושינויי אירועים נעשים בטרנזקציות Serializable; גרסת אירוע מונעת דריסת עדכון ממכשיר אחר.
- תאריכי האירועים והתשלומים נשמרים כ־DATE. "היום" נקבע לפי Asia/Jerusalem. שעות האירוע הן השעות המקומיות שהוזנו.
- לקוח חדש נספר לפי תאריך יצירת תיק הלקוח. לקוח חוזר הוא לקוח עם יותר מאירוע אחד שאינו מבוטל.
- ייצוא טווחי תאריכים מתייחס לתאריך האירוע, גם בייצוא תשלומים. קובצי CSV מקודדים ב־UTF-8 עם BOM ותווי נוסחה מנוטרלים.

## גיבוי

```powershell
npm run db:backup
```

נוצר קובץ JSON מלא בתיקיית `backups`, הכולל לקוחות, סוגים, אירועים ותשלומים בטרנזקציה עקבית. הקבצים מכילים מידע אישי, ולכן אינם נכללים ב־Git. שמרו עותק נוסף במקום פרטי ומאובטח מחוץ למחשב. גיבוי מקומי אינו תחליף לגיבויים של ספק בסיס הנתונים. הגדירו ב־Neon חלון שחזור וגיבוי המתאים לחשבון שלכם. ייצוא CSV מיועד לעיון, ולא לשחזור מלא.

## בדיקות

```powershell
npm run lint
npm run typecheck
npm test
npm run build
# כאשר בסיס הנתונים המקומי ושרת הפיתוח פועלים:
npm run test:e2e
```

בדיקות הדפדפן יוצרות נתוני בדיקה ומוחקות את אירועי הבדיקה; הריצו אותן רק מול בסיס נתונים ייעודי לפיתוח, ללא נתוני עסק אמיתיים. נדרש דפדפן Playwright: `npx playwright install chromium`.

## מסכים וארכיטקטורה

- `src/app/api`: API מאומת, תיקוף שרת, טרנזקציות וייצוא.
- `src/lib/domain.ts`: חישובים כספיים, תאריכים, סינון ונרמול מספרי טלפון.
- `src/lib/events-service.ts`: פעולות אירועים ותשלומים עם הגנות לעדכונים מקבילים.
- `src/lib/validation.ts`: סכמות Zod.
- `src/components`: מסכי העסק, טפסים ורכיבי תצוגה.
- `prisma/schema.prisma` ו־`prisma/migrations`: המודל היחסי והמיגרציות.
- `tests`: בדיקות חישובים ותהליכי דפדפן.

המסכים מקבלים תמונת מצב משותפת מהשרת ומרעננים אותה אחרי שמירה, חזרה לחלון וחידוש החיבור. פתרון פשוט לעסק קטן; לעשרות אלפי רשומות אפשר להוסיף עימוד, סינון שרת וטבלאות צבירה ללא שינוי מודל הנתונים.

## התקנה באייפון

פתחו ב־Safari דרך HTTPS, לחצו על שיתוף ואז "הוסף למסך הבית". יש Manifest, סמלים ועמוד למצב ללא חיבור. לא נשמרים נתונים פרטיים במטמון ולא נרשמים שינויים ללא רשת.
